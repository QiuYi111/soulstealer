四阶段演进

从单点审讯到多Agent互联——垂直切片，逐步验证

壹

审讯逻辑验证

当前阶段

核心目标：跑通终端对话流程，验证嫌犯 Agent 能在生理属性变化下涌现出屈打成招与攀咬行为。

具体任务

  • ✓ Agent 三级缓存：实现 SOUL / Memory / Relationships 的加载、存储和按需调取。
  • ✓ 庭审引擎：构建 CourtSession 核心黑盒，管理生理状态和动作逻辑。
  • ✓ 刑罚 API：实现夹棍、拶指、鞭笞等刑具的确定性数值扣减。
  • ✓ 生理状态提示词注入：将数值状态转化为自然语言描述注入 Agent 提示词。
  • ◎ 涌现行为验证：确认 Agent 在高压下能自主涌现出"屈打成招"和"攀咬无辜"行为，而非硬编码触发。

交付物

一个可以在终端中运行的完整审讯流程：玩家（作为县令）与嫌犯 Agent（阿二）的对话，包含刑罚施加和生理状态变化。

贰

奏折交互系统

计划中

核心目标：县令 Agent 基于原案自动生成明发/密折，玩家可在 TUI 中阅读与批示。

具体任务

  • ○ 奏折生成：官员 Agent 读取 Cases 原案记录，自主撰写明发奏折和密折。
  • ○ 双轨差异：确保同一官员在明发奏折和密折中展现不同的叙事策略。
  • ○ 朱批界面：TUI 中实现奏折阅读和朱批输入的交互界面。
  • ○ 压力传导：朱批内容影响官员 Agent 的政治压力参数，改变后续审讯和奏折行为。
  • ○ 案卷调阅：实现消耗资源调阅原始案卷的机制，与奏折形成信息对比。

交付物

完整的"乾隆视角"体验：玩家阅读奏折、发现破绽、下达朱批、观察官员反应。核心信息博弈闭环完成。

叁

刑罚强化逻辑

计划中

核心目标：细化刑罚 API 对生理属性的扣减规则，增强审讯的压迫感与真实感。

具体任务

  • ○ 累积效应：同一刑具多次使用的效果递减/递增（如反复夹棍会导致永久损伤）。
  • ○ 昏厥机制：当生理状态超过阈值时触发昏厥，需要等待恢复或泼水唤醒。
  • ○ 死亡判定：健康值归零导致嫌犯死亡，案件终止但引发政治后果。
  • ○ 组合刑罚：支持多种刑罚组合使用，模拟真实的审讯策略。
  • ○ 时间流逝：审讯之间的时间流逝影响饥渴值，增加生存压力。

交付物

更真实、更具压迫感的审讯系统。生理状态不再只是数字，而是通过细致的描述和涌现行为让玩家感受到制度性暴力的残酷。

肆

多 Agent 互联

计划中

核心目标：将被攀咬的新人物实例化为 Agent，通过明发奏折触发其他官员的连锁反应。

具体任务

  • ○ 动态实例化：当嫌犯攀咬某人时，系统自动创建新的 Agent 实例（基于模板 + 随机生成背景）。
  • ○ 连锁审讯：新被捕者进入审讯流程，可能继续攀咬更多人。
  • ○ 跨区域联动：明发奏折被其他地区官员读到后，触发新的抓捕和审讯行动。
  • ○ 恐慌指数：全局性的恐慌水平指标，随案件数量和奏折内容动态变化。
  • ○ 系统终局：当恐慌指数达到极端值或皇帝下旨停止追查时，触发系统终局评估。

交付物

一个真正动态的、能自我演化的叫魂恐慌模拟系统。谎言的增殖不再局限于单个审讯室，而是能在整个官僚网络中蔓延。

终极愿景

当阶段四完成时，《叫魂》将不再只是一个"游戏"——它将成为一个可以复现历史动力学的社会学实验平台。每一个 Agent 的选择、每一份奏折的措辞、每一次朱批的压力传导，共同编织出一段独特的历史叙事。
