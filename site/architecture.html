分层架构概览

项目采用务实领域驱动设计（Pragmatic DDD）的三层标准架构，通过物理隔离确保领域逻辑的纯粹性。依赖规则简单而严格：领域层不依赖任何基础设施。

玩家界面层
internal/infrastructure/tui.py
Textual TUI 应用主入口，奏折阅读、朱批输入、案卷查阅
应用服务层
internal/application/
game_session_service archive_service setup_service
编排领域对象，协调庭审、存档、初始化等业务流程
核心领域层
internal/domain/
agent.py agent_builder.py court.py cases.py letters.py
纯业务逻辑——Agent 三级缓存、庭审引擎、奏折系统。不依赖任何外部库
基础设施层
internal/infrastructure/
llm.py persistence.py tui.py
LLM API 客户端、JSON 持久化存储、Textual/Rich TUI 实现
铁律
  1. 领域为王：internal/domain 不得导入 infrastructure 或任何第三方驱动。
  2. 基础设施服务领域：internal/infrastructure 导入 internal/domain，实现领域定义的接口。
  3. 应用层编排：internal/application 导入两者，进行依赖注入和业务编排。

Agent 三级缓存架构

每个 Agent 采用三级缓存结构，将静态人设、动态记忆与外部上下文清晰分离：

L1

SOUL — 永驻层

Agent 的核心人设和背景信息。从 Soul.md 文件加载，作为系统提示词（System Prompt）的一部分始终驻留在上下文中。

文件：agents/{name}/Soul.md 加载频率：每次对话
L2

Memory — 语义记忆层

Agent 的自主语义记录。不是系统日志，而是 Agent 认为重要的观察、判断和推理结果。由 Agent 通过 /update_memory 命令自主写入。

文件：agents/{name}/memory.json 加载频率：按需调取
L3

Relationships & Traits — 外部上下文

与其他角色的关系网络和互动模式，以及 Agent 的细粒度性格特征（trait）。影响 Agent 在特定社交场景中的行为倾向。

文件：agents/{name}/relationships.json, trait.json 加载频率：按需调取

庭审引擎

CourtSession 是审讯系统的核心黑盒引擎，仅负责维护生理状态、执行动作逻辑和记录原始数据：

领域模型
class SuspectState:
    health: int = 100    # 健康
    pain: int = 0        # 疼痛
    thirst: int = 0      # 饥渴
    hunger: int = 0      # 饥饿
    fainted: bool = False

class CourtSession:
    """管理单次庭审的核心黑盒引擎"""
    interrogator: str
    suspect: str
    state: SuspectState
    log: List[Dict]       # 对话记录
    raw_data: List[Dict]  # 结构化原始数据

    def apply_torture(tool, question) -> Dict
    def _get_physiological_desc() -> str

关键设计决策：庭审引擎不产生任何文本内容。所有的格式化输出、奏折撰写、供词生成均由 Agent 在 LLM 层面完成。引擎只管理状态和记录。

刑罚 API

刑罚系统是确定性数值引擎，不同的刑具对应不同的属性扣减：

刑具 疼痛增加 健康减少 描述
夹棍 +30 -15 夹碎脚骨，钻心之痛
拶指 +20 -5 夹断手指，剧痛难忍
鞭笞 +15 -8 皮开肉绽，鲜血淋漓
掌嘴 +5 -2 打肿面颊，轻微痛苦

奏折领域模型

LettersSystem 管理奏折的双轨流转，包括报告的创建、朱批的附加和状态追踪：

领域模型
class Report:
    id: int
    type: str            # "明发奏折" | "密折"
    content: str         # 奏折正文
    author: str          # 撰写官员
    timestamp: str
    rescripts: List[Rescript]  # 朱批列表
    raw_case_data: str   # 原始案卷全记录
    polished_case_data: str    # 润色后的案卷
    is_returned: bool    # 是否已发回重审

class Rescript:
    content: str    # 朱批内容
    row: int        # 行位置
    col: int        # 列位置
    timestamp: str

奏折的正文由官员 Agent 基于 Cases（案卷记录）自主撰写。系统不干预写作内容——官员可能如实汇报，也可能选择性省略、美化甚至编造。朱批由玩家在 TUI 界面中直接在奏折文本上标注位置写入。

技术栈

Python 3.11+

核心开发语言，利用 dataclass 和类型注解构建清晰的领域模型。

Textual

现代终端 UI 框架，支持丰富的布局、面板和交互组件，构建高质量 TUI。

Rich

终端富文本渲染库，处理排版、色彩和格式化输出。Textual 的底层依赖。

OpenRouter

LLM API 聚合网关，支持动态切换 DeepSeek、Qwen 等模型，为 Agent 提供智能决策。

uv

Rust 编写的超高速 Python 包管理器，替代 pip 和 poetry，管理依赖和虚拟环境。

RAG

向量检索增强生成系统，为 Agent 提供基于历史文档的上下文检索能力。
